## Compatibility result

The installed port is **incompatible** with the Exoframe implementation-engine
contract, so the implementation engine is **unavailable**. The port declares
skills, but it does not satisfy these required public capabilities:

- `plugin.name`
- `plugin.version`
- `manifest.agents`
- `skills.poteto-mode`
- `agents.poteto-agent`

The exact supported reference identity/version is `pstack` version `0.14.5`.
A different package or release is not assumed to be an equivalent
implementation engine.

This result does not reject the installed skills as advisory tools. It means
only that this skills-only port cannot provide the autonomous pstack engine
that the Exoframe MVP contract requires.

## Metrics baseline

There is no Exoframe run history and there are no completed Exoframe runs to
measure. Every recorded metric therefore has `sample_count` 0 and `value` null.
These values mean "unknown," not zero defects, zero cost, or successful
autonomy. Real observations replace this empty baseline only after Exoframe
executes completed runs.

The metric schema preserves its intended cohorts:

- Automatic merge rate covers only eligible R0/R1 tasks.
- Risk-cohorted defect and rollback rates stay separate for R0, R1, R2, and R3.
- Task-to-engineering-ready and task-to-merge durations remain distinct.

## Reproduction

Run the read-only collector with the committed contract and an explicit plugin
root, preserving the recorded base SHA and observation timestamp when checking
byte-for-byte reproducibility. `--silent` suppresses npm's banner so stdout
equals the JSON artifact.

```sh
npm run --silent baseline:s0.4 -- --contract docs/baselines/s0.4-pstack-contract.json --plugin-root <pstack-plugin-root> --base-sha bc3466120576c5d4823f298599d011549e98da0d --observed-at 2026-09-01T15:33:58.000Z
```
